## What this is

First public beta of the GitHub Relay V1 distribution of ChatGPT Codex Bridge:
one ChatGPT web conversation supervises local Codex work on your own Mac via
labeled Issues in your own private control repository. Derived from
`larryppgg/chatgpt-codex-bridge` (MIT); adds GitHub Relay multi-project
management. Community package, not an OpenAI product.

## Highlights

- GitHub Relay V1 primary path: outbound-only local relay, strict closed
  request schema, allowlisted authors, per-alias registry binding, isolated
  Git worktrees, guarded publish of generated branches only.
- Legacy Secure MCP Tunnel transport retained and regression-tested; not a
  Relay dependency.
- Fresh-only V1 installer with explicit `--no-start` semantics
  (`POLICY_SUPPORT=NOT_PROBED`, `PLIST_DEFAULT_DISABLED=true`,
  `LAUNCHD_STATE=NOT_PROBED`, `SERVICE_STARTED_BY_INSTALLER=false`).
- Bilingual Quick Start, controller SOP with capability precheck, static
  verification SOP, synthetic job examples validated against the closed
  schema.

## Known limitations (summary)

- macOS LaunchAgent only; no Windows/Linux service packaging.
- Web controller path requires your session to actually hold GitHub write
  tools for your private control repository; read-only sessions cannot drive
  it.
- No exactly-once or multi-tenant claims; states are distinct (completed,
  delivered, review-accepted, published, merged, deployed).
- Control repository stores task requests and sanitized diffs; apply your
  project data policy.
- Fresh-only install: no upgrade/recovery adoption of existing Bridge state.

## Upgrade / rollback

- From legacy Tunnel 0.6.x: different transport and store; finish old work
  first. The fresh V1 installer rejects existing state
  (`FRESH_INSTALL_REQUIRED`); do not rerun it to adopt partial state.
- Rollback of the relay itself is not supported by this installer; recovery is
  a separately reviewed operation.
